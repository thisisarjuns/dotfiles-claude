# CLAUDE.md OMC Block Boundary

## The Insight
`~/.claude/CLAUDE.md` is partially machine-managed. Anything between `<!-- OMC:START -->` and `<!-- OMC:END -->` is regenerated by `omc update` (current version banner: `<!-- OMC:VERSION:X.Y.Z -->`). Custom user content placed inside that block disappears the next time the user updates oh-my-claudecode.

## Why This Matters
A user asking Claude to "add a global rule" or "make Claude always do X" expects persistence across conversations AND across tool updates. If the directive lands inside the OMC block, it survives until the next `omc update` then vanishes silently - no error, no warning, just gone. The user will think Claude lied about saving it.

## Recognition Pattern
- User says: "add to CLAUDE.md", "global directive", "always do X", "every conversation should...", "make it permanent"
- File starts with `<!-- OMC:START -->` and ends with `<!-- OMC:END -->`
- Settings.json shows `enabledPlugins` containing `oh-my-claudecode@omc` or similar OMC marketplace entry

## The Approach
1. Read the file. Confirm it has OMC markers.
2. Append the new directive AFTER the `<!-- OMC:END -->` line, never before it or inside.
3. Wrap your addition in your own paired markers (e.g. `<!-- USER:LEARNING:START -->` / `<!-- USER:LEARNING:END -->`) so future edits can find and update it idempotently.
4. Don't modify content inside OMC markers - any fix to OMC's defaults belongs upstream in the omc plugin repo, not in the user's local file.

## Example
```markdown
<!-- OMC:END -->

<!-- USER:LEARNING:START -->
<learning>
... custom directive ...
</learning>
<!-- USER:LEARNING:END -->
```

The marker pair pattern also lets a future `Edit` call locate the block deterministically by anchoring on `<!-- USER:LEARNING:START -->`.
